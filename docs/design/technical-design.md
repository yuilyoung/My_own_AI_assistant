# 개인 AI 비서·가상 소개팅 공통 엔진 기술 설계

기준일: 2026-10-29. 대상 저장소: `yuilyoung/My_own_AI_assistant`.

이 문서는 기존 Live2D 공통 엔진 v0.1 설계를 저장소용으로 정리하고 v0.2 부분 구현과의 차이를 명시한 통합판이다. 설계 목표와 구현 완료를 혼동하지 않는다. 구현 상태는 [../implementation-status.md](../implementation-status.md)를 우선한다.

## 1. 목표와 범위

현재 Windows 로컬 PC에서 한국어 개인 비서와 가상 소개팅을 공통 엔진으로 실행한다. Mac mini는 아직 보유하지 않았으며 향후 서버 이전 대상으로만 취급한다. 브라우저는 입력·음성 재생·Live2D 렌더링을 담당하고 서버는 대화·기억·추론을 담당한다.

최종 1차 MVP: 고정 Live2D 모델 1개, 텍스트/버튼식 음성 입력, 한국어 음성 응답, 음량 기반 립싱크, 비서/소개팅 모드, 명시적으로 저장한 기억, 앱 내부 메모. 할 일, VAD, 외부 일정·이메일·Codex는 후속이다.

공통화하는 것은 코드와 공급자 인터페이스다. 개인 기억, 작업 권한, 자격 증명을 공유하지 않는다. 소개팅은 가상 성인 캐릭터임을 표시하며 실제 사람으로 속이지 않는다.

초기 제외: 결제, 모바일 스토어 배포, 다중 사용자 호스팅, 자유로운 모델 업로드, 실시간 영상 생성, 음성 복제, 카메라 감정 추정, 상시 마이크, 임의 셸 실행. 기존 PC 비용을 제외하고 유료 API·구독·유료 자산을 필수 조건으로 만들지 않는다.

## 2. 구현 선택

| 접근 | 판단 |
|---|---|
| Open-LLM-VTuber 전체 포크 | 비교·참고 대상으로만 사용. 프런트엔드 등 구성요소별 배포 조건을 별도 확인해야 한다. |
| 자체 최소 엔진 + 검증된 구성요소 | 채택. 모드별 기억·권한 경계와 공급자 교체를 직접 통제한다. |
| Unity 전체 앱 | 이번 웹·2D·로컬 MVP 범위에서는 제외한다. |

계획한 화면은 React + TypeScript + Vite + 공식 Cubism SDK for Web이다. **현재 코드는 React/Live2D가 아니라 HTML/JavaScript 개발용 진단 화면이다.** 의존성 설치가 막힌 이전 환경에서 대체 진단 경로를 만들었으며, 이를 완성된 캐릭터 UI로 표시하지 않는다.

## 3. 시스템 구조

```text
브라우저
  채팅 / 명시적 마이크 입력 / 중지 / 기억 관리
  Web Audio 재생 / RMS 계산 / 향후 Live2D Canvas
                      |
             동일 출처 로컬 HTTP
                      |
FastAPI Gateway + 공통 엔진
  입력 검증 / 세션·턴 / 취소·generation / 모드 정책
  범위별 기억 / 구조화 응답 검증 / 제한된 비서 메모
          |            |             |             |
       SQLite        Ollama      whisper.cpp     MeloTTS
                                  자식 프로세스   격리 워커
```

처음부터 마이크로서비스·Redis·Kubernetes·벡터 DB를 도입하지 않는다. Gateway와 엔진은 모듈화된 단일 앱이다. STT는 별도 자식 프로세스, TTS는 별도 워커로 두어 모델 의존성과 요청 처리를 분리한다. 현재 STT CLI는 발화마다 모델을 로드한다. 상주 워커 최적화는 후속이다.

브라우저가 Ollama나 음성 워커를 직접 호출하지 않는다. 현재 전달 방식은 인증된 HTTP 조회/폴링이다. 최종 WebSocket 이벤트 전송은 같은 세션·턴·세그먼트 경계를 유지하며 후속으로 교체한다.

## 4. 공급자와 실행 프로필

| 영역 | 선택 | 현재 준비 수준 |
|---|---|---|
| 서버 | Python/FastAPI/Pydantic | 구현·자동 테스트 |
| 저장 | SQLite | 모드 범위 분리 구현 |
| LLM | Ollama, 초기 모델 후보 Qwen3-4B | 모의 HTTP 계약 검증, 실제 품질 미검증 |
| STT | whisper.cpp 다국어 모델 | CLI/입력/취소 계약 검증, 실제 한국어 모델 미검증 |
| TTS | MeloTTS Korean | HTTP 어댑터·선택형 워커, 실제 추론 미검증 |
| 캐릭터 | 공식 Cubism Web SDK + 고정 모델 | 미구현, Core/모델 미포함 |
| VAD | Silero VAD 후보 | 후속 |

`demo`: 고정 응답, 음성 기본 없음, 가상 데이터용 저장 공간. 실제 AI가 작동했다고 표현하지 않는다.

`local_private`: Ollama·로컬 음성 경로. 클라우드 자동 fallback 금지. Gateway의 loopback URL 검사와 Ollama 서버의 `OLLAMA_NO_CLOUD=1`을 함께 적용한다. 최초 모델 다운로드와 런타임 외부 전송은 다르며 완전한 오프라인 동작은 실기기에서 별도 시험한다.

후속 `cloud_demo`: 무료 API 비교 전용 가상 데이터 DB. 실제 개인 기억을 복사하지 않는다. 가격표·계정 할당량·데이터 이용 조건을 재확인하고 활성화한다. 무료 구간 소진 시 유료 공급자로 자동 전환하지 않는다.

후속 `personal_connected`: 외부 모델/도구로 전송할 정보와 권한을 표시하고 별도 동의를 받는 프로필. 로컬 장애가 이 프로필의 자동 활성화 사유가 되지 않는다.

## 5. Live2D 자산과 표현

Live2D는 영상 조각 합성이 아니라 준비된 그림·리깅의 런타임 제어로 구현한다. 모델 진입점 `.model3.json`, `.moc3`, textures, expressions, motions, physics 및 앱의 자산 manifest를 분리한다. 모델 출처·revision·해시·이용 조건·재배포 검토 상태를 기록한다.

상태와 감정을 구분한다. 상태는 idle/listening/thinking/speaking/interrupted/error, 감정은 neutral/happy/concerned/surprised 등 제한된 코드다. 이는 캐릭터 표현이며 사용자의 실제 감정을 진단하는 결과가 아니다.

```json
{"segments":[{"text":"오늘은 어떤 하루였어?","emotion":"happy","gesture":"nod"}]}
```

LLM 출력은 허용 목록과 길이를 검증한다. 임의 파일 경로·JavaScript·SDK 명령은 실행하지 않는다. 캐릭터가 지원하지 않는 동작은 중립으로 대체한다. 모델에 없는 손동작을 생성한다고 주장하지 않는다.

기본 호흡·눈 깜빡임은 런타임, 큰 몸짓은 준비된 motion, 표정은 expression/제한된 파라미터 조합이다. 립싱크는 실제 재생 오디오 RMS → gain/clamp → smoothing → LipSync 그룹 파라미터로 매핑한다. 특정 입 파라미터가 모든 모델에 존재한다고 하드코딩하지 않는다.

동기화 기준은 서버 생성 시간이 아니라 브라우저 AudioContext의 실제 재생 시각이다. 말하는 동안 입 파라미터의 최종 소유권을 립싱크에 두고 모션과 충돌하지 않게 한다. 중지 시 버퍼를 버리고 입을 닫는다. **음량 기반 입 벌림은 한국어 음소별 정확한 립싱크가 아니다.** 현재 진단 UI는 RMS 막대만 표시한다.

## 6. 대화와 음성 상태

텍스트 또는 PTT → 입력 검증 → 전사 결과 검토 → 명시적 전송 → 해당 모드의 기억·정책 → LLM → 응답 검증 → 문장별 TTS → 재생 순서다. 전사를 자동으로 채팅에 제출하지 않는다.

PTT는 AudioWorklet에서 실제 sample rate의 PCM을 수집하고 16kHz 모노 PCM16 WAV로 리샘플링한다. 서버는 파일 확장자만 신뢰하지 않고 RIFF·데이터 길이·포맷·길이를 검사한다. v0.2 입력은 0.1~30초, 최대 업로드 964096바이트다. 정확한 0 신호 거부는 VAD가 아니며 잡음 오인식은 사용자의 결과 확인이 필요하다.

세션/턴/generation/세그먼트 식별자를 사용한다. 중지·새 대화·모드 전환은 이전 generation을 무효화한다. 하위 추론이 즉시 멈추지 못해도 오래된 결과는 서버와 클라이언트 모두 버린다. 재생 중단은 오디오 source와 예정 버퍼를 제거하며 입 상태를 초기화한다.

마이크 승인 대기 중 취소, 업로드 직후 모드 전환, 디코딩 중 취소, 오래된 STT 결과 도착을 회귀 테스트한다. 녹음 완료/오류/취소에서 마이크 트랙을 종료한다. 원본 녹음과 CLI 결과는 임시 폴더에서 처리하고 정리하지만 강제 종료·전원 장애 및 디스크 복구까지 방지하는 보안 삭제는 보장하지 않는다.

문장별 합성/재생은 샘플 단위 네이티브 음성 스트리밍과 다르다. 불완전한 JSON·추론 채널·도구 결과를 TTS로 읽지 않는다. 자동 VAD와 양방향 끼어들기는 PTT 안정화 이후이며 에코 제거는 별도 과제다.

## 7. 기억과 권한

서버가 scope를 결정한다. 비서는 `assistant`, 소개팅은 `companion:{character_id}`다. 초기 고정 캐릭터는 default이다. 모드 변경은 새 세션이며 대화·입력창을 교차 복사하지 않는다.

기억은 명시적으로 저장한 사실만 사용한다. 자동 추출·요약·벡터 검색은 현재 없다. 기억 목록/저장/삭제와 모드별 최근 대화를 제공한다. 자동 기억 추출을 도입할 때 삭제한 원문으로부터의 재생성을 막는 삭제 정책을 추가한다.

소개팅에 비서 도구를 등록하지 않는다. 비서의 초기 도구는 앱 내부 메모 생성/조회이며 외부 캘린더에 저장했다고 말하지 않는다. 클라이언트가 직접 전송한 사용자 ID나 scope로 권한을 결정하지 않는다. LLM이 스스로 모드를 변경하거나 권한을 올릴 수 없다.

SQLite는 암호화 저장소가 아니다. 같은 OS 계정·관리자에 대한 보호는 별도 OS 보안에 의존한다. 로그는 소요시간·오류코드·모델명 중심이며 토큰·대화 원문을 기본 로그로 출력하지 않는다.

## 8. 모듈과 API 책임

| 모듈 | 책임 |
|---|---|
| config / contracts | 환경 설정, loopback 공급자 제한, 응답 스키마 |
| policy | Persona, 모드·기억 범위, 비서 도구 허용 |
| store | SQLite 세션·기억·메모·메시지 |
| engine | 턴 수명주기, 취소, LLM/TTS, 단기 오디오 |
| providers | 고정 demo / Ollama / Melo 어댑터 |
| speech / transcription | WAV 검증, whisper 자식 프로세스, 전사 작업 |
| api / cli | 로컬 인증·Host/Origin·입력 크기, HTTP, 시작 |
| diagnostics | 폼·기억 관리·오디오·마이크·취소 상태 |

현재 구현의 정확한 경로와 입력 스키마는 FastAPI OpenAPI 및 코드/테스트가 기준이다. 설계의 최종 WebSocket 이벤트는 turn.started, stt.final, response.segment, audio.ready, turn.completed/cancelled, error로 발전시킨다. 오디오는 대형 base64 JSON이 아니라 인증된 단기 HTTP 리소스로 제공한다.

오디오 ID를 실제 파일 경로로 받지 않는다. 다른 세션에서 오디오/전사 작업을 읽지 못하게 검사한다. 재연결은 상태 조회이지 도구 재실행·과거 오디오 재생의 허가가 아니다.

## 9. 보안 경계

Gateway는 사용자 권한으로 127.0.0.1에만 바인딩한다. SYSTEM/관리자 권한이 필요하지 않다. 동일 출처 진단 UI, Bearer 토큰, Host/Origin 검사, 입력 크기 제한을 적용한다. 토큰은 콘솔 URL fragment를 통해 로컬 탭으로 전달한 뒤 주소창에서 지운다. 장기 비밀을 query·프런트 번들·Git에 넣지 않는다.

외부 모델 출력·문서·전사문은 비신뢰 데이터다. shell 문자열을 웹 서버에서 실행하지 않는다. STT는 고정 argv의 subprocess 경로이며 작업 디렉터리와 시간을 제한한다. TTS 워커는 별도 토큰·loopback 바인딩이다.

demo와 local_private DB를 분리한다. 음성 캐시·전사 작업은 용량/수/만료를 제한한다. 현재 만료 정리는 요청 시 이뤄지므로 엄격한 실시간 삭제 보장이라고 설명하지 않는다. 공개 터널·포트 포워딩은 이번 범위에서 금지한다.

## 10. Mac mini와 Codex 후속 경계

Mac mini로 Gateway·DB·모델 프로세스를 옮겨도 입력·재생·렌더링은 사용자의 브라우저에 둔다. API/DB/Persona를 유지하고 실행 파일·Python·모델 런타임은 ARM64/macOS에 맞게 재검증한다. Windows 바이너리를 복사하는 포팅이 아니다.

다른 기기의 브라우저 마이크에는 HTTPS 등 보안 출처와 원격 인증이 필요하다. 평문 LAN 주소를 localhost와 동등하게 취급하지 않는다. 자동 시작·재시작·절전·백업·로그 회전은 별도 운영 기능이다. 24시간 서버 대기는 24시간 모델 추론이 아니며 요청 없는 무한 루프를 만들지 않는다.

Codex는 기본 대화 엔진이 아니라 비서 전용 작업 어댑터 후보다. 지원되는 인증 방식·구독 한도/API 과금·이용 조건을 연결 시 확인한다. 전용 작업 폴더·사용자 승인·시간/네트워크/파일 권한 제한을 적용한다. 로컬 프로세스라도 모델 데이터가 외부로 나가는 구성이면 local_private에서는 끈다.

## 11. 인수 기준과 단계

M0 자산·라이선스·실기기 모델 검증 → M1 React/Live2D+텍스트 → M2 음성+재생 동기화 → M3 두 모드/기억/도구 → M4 VAD·운영 → M5 Mac mini·공개 배포 검토.

현재는 공통 엔진·진단 화면·PTT 경로를 먼저 부분 구현했다. 이것은 전체 순서의 완료가 아니다. 다음 시각 구현은 고정 모델+실제 Live2D+재생 RMS 연결이다.

필수 시험: 모드 간 기억 누출 없음, 소개팅의 비서 도구 접근 거부, 취소 후 과거 음성/전사 폐기, 잘못된 공급자 JSON 실패, 다른 세션 오디오 차단, 원격 Host/Origin 차단, 마이크 권한 거부, 모델 미설치의 명확한 오류.

성능 목표는 warm 발화 종료~첫 음성 p50 3초/p95 6초, 중지 후 음성 종료 200ms 이내로 제안한다. **실측 결과가 아니다.** cold/warm, STT/LLM/TTS/재생 지연, 메모리, 한국어 CER/발음, 30분 대화·세션 반복·워커 재시작을 따로 기록한다.

공개 배포 전 Live2D SDK/캐릭터 권리, 모델·목소리 라이선스, 인증/테넌트 격리, 개인정보 보존·삭제, 비용·악용 제한과 운영 검토를 통과해야 한다. 1인 로컬 테스트 통과를 서비스 출시 가능 판정으로 사용하지 않는다.
